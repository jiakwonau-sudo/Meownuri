- *중요:* **기존 공개 main을 아직 교체하지 않았다.** 수정 파일은 검증용 별도 빌드다.

## 2. 모바일 빈 화면

**제출 이미지 관찰:** 상태/미션/조이스틱/점프 UI는 보이고 월드 렌더링 영역은 단색의 살구색이었다. 이것만으로 Android 실제 GPU 실패 원인을 확정할 수 없다.

**현장 재현:** QA용 Chromium의 제한된 GPU/WebGL 환경에서 원본 엔진의 `THREE.WebGLRenderer` 생성 실패와 페이지 앱 시작 실패를 재현했다. HTML UI는 Canvas와 독립이므로 남을 수 있다.

**개선 사항:**
1. WebGL Renderer 생성 실패시 2D 안전 렌더러로 자동 전환.
2. 게임 도중 `webglcontextlost` 또는 렌더링 예외 발생시 2D 안전 렌더러로 전환.
3. WebGL 컨텍스트는 유효해도 월드가 4회 연속 균일한 단색인 경우 픽셀 기반 감지 후 2D 전환(정상 GPU에서의 오탐/동작은 **미검증**).
4. 비정상 카메라 거리·Yaw/Pitch·플레이어 좌표 가드 추가.
5. 2D 안전 모드는 캐릭터 위치, 목표 표시, 배경 지형, 보유 UI 및 터치 조작을 원래 게임 객체와 연결.
6. 말풍선을 숨기되, 조작 안내 텍스트와 기존 BGM에 영향을 주는 이벤트 문자열은 일괄 삭제하지 않음.

**제한:** 정상 WebGL이 가능한 실제 휴대전화에서 3D 렌더러와 화면 전환, 프레임 속도를 다시 검사해야 한다. 2D 안전 모드는 설계상 간소화된 대체 화면이며 3D 결과를 증명하지 않는다.

## 4. 계획과 실제 구현의 차이

v16.0은 Day4–10의 **진행 가능한 인터랙티브 장면 골격**이다. 다음은 아직 최종 완성되지 않았다.

- 원 기획의 하루 10~15분 플레이 타임: 현재 4~6개 목표/날짜이므로 전체 볼륨 **미달**.
- 곰의 몸통 박치기·피격·도망 애니메이션과 카메라 컷 전환은 기획 수준; 현재 기본 NPC 이동/몸짓·배치만 구현.
- 동물들의 목소리 없는 감정 표현은 기본 움직임/상대 거리/제스처. 세밀한 귀/눈/표정 모핑 및 감정 페이싱은 미완료.
- Day7 세 번째 '마을 이름 직접 입력'은 아직 세 번째 미리 정한 이름으로 대체. 원 계획과 다른 점이므로 후속 구현 필요.
- Day4 역할 배정은 기본 4역할 확정 플래그, 사용자가 각 고양이에게 직접 배정하는 미니게임은 미구현.
- 화면의 게임 목표는 명확하지만 Day4–10은 아직 원래 세상의 별도 지형을 사용하는 완전히 다른 왕궁 환경으로 재구축되지 않음.

## 5. 재현 방법

1. `index.html`을 정적 HTTPS 호스팅에서 연다(파일 자체는 외부 JavaScript 의존 없음).
2. `새로 시작`을 눌러 게임 화면/조이스틱/배경을 확인한다.
3. Day 3 마지막 선택을 마치고 📖을 눌러 Day 4를 시작한다.
4. Day4–10에는 점선/원형 목표를 따라 이동, 목표에 접근하면 하단 중앙 행동 버튼 활성.
5. Day5/7/9 선택을 실제 클릭하고, 새로고침·이어하기·Day10 분기를 확인.
6. 화면이 단색으로 유지되면 콘솔 로그 `[MEOWNURI]`와 `rendererMode`(2d/3d)를 함께 확인한다.

**확인 자료:** `SOL_DAY04-10_SCREEN_CONTACT_SHEET.jpg` 및 `screenshots/` 각 날짜 시작/완료/엔딩 화면. 이 캡처들은 원본 3D가 아니라 2D 안전 모드이며 **이미지 생성물이 아닌 브라우저 실제 캡처**다.

## 6. 배포 원칙

실제 Android에서 정상 WebGL·저장 복원 확인 전에는 `main` 생산 배포를 바로 덮어쓰지 않는다. GitHub에는 별도 검토 브랜치로 우선 보관한다. 이 후 결과가 합격하면 기존 공개 주소에 반영한다.
